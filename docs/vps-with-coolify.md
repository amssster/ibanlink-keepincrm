# IBAN Link: розгортання на власному VPS через Coolify (Docker Compose)

Покрокова інструкція з розгортання **IBAN Link для KeepinCRM** на власному сервері VPS за допомогою панелі [Coolify](https://coolify.io).

---

## Чому Coolify?

Coolify надає зручний веб-інтерфейс, автоматичний випуск і оновлення безкоштовних SSL-сертифікатів (Let's Encrypt), моніторинг ресурсів та оновлення додатків через Git без необхідності вручну працювати в терміналі через SSH.

У стандартному файлі `compose.yaml` передбачено власний веб-сервер Caddy для портів 80/443. Оскільки Coolify має власний вбудований зворотний проксі (Traefik або Caddy), для уникнення конфлікту портів використовується готовий конфіг **`compose.coolify.yaml`** (без дублюючого Caddy).

---

## 1. Підготовка

1. **VPS з Coolify:** працюючий сервер із встановленою панеллю Coolify.
2. **Домен:** спрямуйте A-запис потрібного піддомену (наприклад `pay.mybusiness.ua`) на IP-адресу вашого VPS сервера в панелі реєстратора домену або в Cloudflare (з увімкненим або вимкненим проксі).
3. **Секрети:** згенеруйте надійні токени та паролі перед деплоєм (див. крок 4).

---

## 2. Створення ресурсу в Coolify

1. Відкрийте панель Coolify.
2. Перейдіть у розділ **Projects** → оберіть ваш проєкт та середовище (наприклад, `Production`).
3. Натисніть **+ New Resource**.
4. Оберіть **Git Repository**.
5. Виберіть тип репозиторію:
   - **Public Repository:** вставте посилання на репозиторій:
     `https://github.com/amssster/ibanlink-keepincrm`
   - **Private Repository:** оберіть підключений GitHub App / Deploy Key, якщо ви використовуєте власний приватний форк.
6. Вкажіть гілку (Branch): `main`.
7. У пункті **Build Pack** оберіть **Docker Compose**.
8. Натисніть **Save**.

---

## 3. Налаштування Docker Compose

Після створення ресурсу Coolify відкриє сторінку налаштувань:

1. Знайдіть поле **Docker Compose Location** або вибір конфігураційного файлу.
2. Вкажіть шлях до адаптованого файлу:
   ```text
   /compose.coolify.yaml
   ```
   *(Або перейдіть у вкладку **Docker Compose** і переконайтеся, що вміст відповідає файлу `compose.coolify.yaml` з репозиторію).*
3. Збережіть зміни (**Save**).

---

## 4. Налаштування домену та маршрутизації

У розділі налаштувань додатку в Coolify:

1. Перейдіть до списку сервісів (або вибору сервісу для домену) і переконайтеся, що домен прив'язано саме до сервісу **`web`** (порт `3000`):
   ```text
   https://pay.mybusiness.ua
   ```
2. **Важливо:** для сервісу **`migrate`** поле домену обов'язково залиште **порожнім**. Якщо Coolify автоматично підставить домен у `migrate`, проксі Traefik спрямує трафік на тимчасовий контейнер міграцій (який вимикається після старту) і браузер показуватиме помилку `503: no available server`.
3. Coolify автоматично згенерує мітки Traefik для `web:3000` та замовить безкоштовний SSL-сертифікат Let's Encrypt.

---

## 5. Налаштування змінних оточення (Environment Variables)

Перейдіть на вкладку **Environment Variables** у Coolify та додайте такі змінні:

| Змінна | Приклад значення | Опис |
|---|---|---|
| `APP_URL` | `https://pay.mybusiness.ua` | Повний origin без завершального слешу |
| `POSTGRES_USER` | `iban` | Користувач бази даних |
| `POSTGRES_DB` | `iban` | Назва бази даних |
| `POSTGRES_PASSWORD` | *(згенерувати)* | Пароль до PostgreSQL |
| `SESSION_SECRET` | *(64 hex-символи)* | Ключ підпису cookie сесій |
| `OWNER_PASSWORD` | `МійНадійнийПароль123` | Пароль для входу в кабінет (від 16 символів) |
| `OWNER_PASSWORD_HASH` | *(опціонально)* | Scrypt-хеш пароля (якщо не використовується `OWNER_PASSWORD`) |
| `WEBHOOK_ISSUE_SECRET` | *(64 hex-символи)* | Секрет тригера угод (`/api/webhooks/keepincrm/issue`) |
| `WEBHOOK_PAYMENT_SECRET` | *(64 hex-символи)* | Секрет тригера фінансів (`/api/webhooks/keepincrm/payment`) |

> **Критично важливо при зміні змінних оточення в Coolify:**
> - Натискання кнопки **«Update Variable»** зберігає значення тільки в базі панелі Coolify.
> - **Працюючий Docker-контейнер НЕ підхоплює змінені змінні автоматично!**
> - Щоб нові або змінені секрети запрацювали, після зміни змінних обов'язково перейдіть на сторінку ресурсу та натисніть **Redeploy** (або Restart).
> - До перезапуску додаток продовжить працювати зі старими значеннями і повертатиме `401 {"error":"Недозволений запит"}` у KeepinCRM.

### Як швидко згенерувати секрети:

**Варіант А (через термінал на локальному комп'ютері):**
```sh
npm run secrets
```
Скрипт запитає пароль власника у видимому вводі та збереже згенеровані значення в `tmp/generated.env`. Захистіть або видаліть цей файл після перенесення секретів.

**Варіант Б (через команду node):**
```sh
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```
Запустіть тричі, щоб отримати окремі значення для `SESSION_SECRET`, `WEBHOOK_ISSUE_SECRET` та `WEBHOOK_PAYMENT_SECRET`.

---

## 6. Запуск (Deploy)

1. У верхньому правому кутку Coolify натисніть кнопку **Deploy**.
2. Відкрийте журнал складання (**Build Logs**):
   - Coolify завантажить код та збере образ контейнера.
   - Запуститься сервіс бази даних `db` і пройде перевірку здоров'я (`healthcheck`).
   - Контейнер `migrate` автоматично застосує SQL-схему та міграції бази даних.
   - Запустяться основний веб-сервіс `web` та планувальник резервних копій `backup`.
3. Після завершення перевірте вкладку **Logs** сервісу `web` — він має вивести повідомлення про запуск на порту 3000.

---

## 7. Перевірка роботи та вхід

1. Відкрийте у браузері:
   ```text
   https://pay.mybusiness.ua/login
   ```
2. Введіть пароль власника, вказаний у `OWNER_PASSWORD` (або для якого було згенеровано `OWNER_PASSWORD_HASH`).
3. Ви потрапите в кабінет керування.
4. Перейдіть у розділ **«Отримувачі»** та створіть ваші банківські реквізити (ФОП, ТОВ, IBAN, призначення платежу).

---

## 8. Підключення до KeepinCRM

Після успішного входу та додавання отримувачів налаштуйте вихідні вебхуки в CRM:

👉 **[Детальна інструкція з налаштування KeepinCRM Webhooks](keepincrm-webhooks.md)**

Коротко:
- В угодах KeepinCRM створити поле `Посилання на оплату IBAN` та список `Отримувач платежу`.
- Додати два тригери: на генерацію посилання (подія зміни етапу) та на фіксацію оплати (з розділу «Фінанси»).
- Вставити відповідні токени `WEBHOOK_ISSUE_SECRET` та `WEBHOOK_PAYMENT_SECRET`.

---

## 9. Оновлення та резервні копії

- **Оновлення коду:** У Coolify увімкніть **Webhook** або **Auto Deploy** при появі нових комітів у гілці `main`. При повторному натисканні **Deploy** Coolify оновить контейнери без втрати даних (база даних зберігається в Docker volume `database`).
- **Резервні копії:** Контейнер `backup` створює дамп при старті та приблизно кожні 24 години в Docker volume `backups`; старіші за 14 днів файли видаляються під час успішного створення копії. Дампи не зашифровані й можуть містити персональні дані та токен Telegram. Обмежте доступ, зберігайте зашифровані копії поза сервером та перевіряйте відновлення за [інструкцією](../README.md#резервне-копіювання-docker).

---

## 10. Типові помилки та їх вирішення

### «503: no available server» при відкритті сайту
- **Причина:** Coolify призначив домен сервісу `migrate` замість `web`. Контейнер `migrate` виконує міграцію і завершує роботу, тому Traefik бачить 0 активних серверів.
- **Вирішення:** У налаштуваннях додатку в Coolify видаліть домен із сервісу `migrate` і вкажіть його для сервісу `web` (порт 3000), після чого натисніть **Deploy**.

### Помилка «password authentication failed for user "iban"» у логах `migrate`
- **Причина:** Значення `POSTGRES_PASSWORD` у вкладці Environment Variables було змінено вже після того, як база даних була вперше ініціалізована. PostgreSQL зберігає початковий пароль у томі даних і не оновлює його з env автоматично.
- **Вирішення:**
  - Не видаляйте том із потрібними даними. Перед змінами створіть резервну копію та перевірте відновлення.
  - Зупиніть записи застосунку. У приватному терміналі сервісу `db` підключіться до PostgreSQL (замініть `iban` на фактичні `POSTGRES_USER` і `POSTGRES_DB`):
    ```sh
    psql -U iban -d iban
    ```
    У `psql` виконайте `\password iban`, двічі введіть новий пароль без відображення та завершіть сеанс командою `\q`. Використовуйте hex-пароль для сумісності з `DATABASE_URL`. Не вводьте пароль у командний рядок або SQL.
  - Задайте той самий `POSTGRES_PASSWORD` у Coolify та виконайте **Redeploy**, щоб усі сервіси отримали нове значення. Перевірте підключення й відновіть роботу застосунку. Зміна змінної сама по собі не змінює пароль PostgreSQL.

### Спеціальні символи в паролі до бази
- Уникайте символів `@`, `:`, `#`, `/`, `?` у значенні `POSTGRES_PASSWORD`, оскільки вони ламають рядок підключення `DATABASE_URL`. Використовуйте чистий hex (наприклад, згенерований через `npm run secrets`).

### Помилка 401 («Недозволений запит») у KeepinCRM при виклику вебхуків
- **Причина 1:** Змінні `WEBHOOK_ISSUE_SECRET` або `WEBHOOK_PAYMENT_SECRET` змінено/додано в Coolify, але не виконано **Redeploy**. Працюючий контейнер `web` очікує старі значення.
- **Причина 2:** Переплутано секрети (наприклад, значення `WEBHOOK_PAYMENT_SECRET` вставлено в тригер угод `/issue`). Для кожного з двох тригерів повинен використовуватися свій секрет.
- **Причина 3:** У полі заголовка в KeepinCRM пропущено префікс `Bearer ` або додано зайві пробіли/переноси рядків.
- **Вирішення:** У Coolify натисніть **Redeploy**. Перевірте відповідність секретів для кожного з двох тригерів. Переконайтеся, що заголовок має формат `Bearer <повний_ключ_без_пробілів>`.
