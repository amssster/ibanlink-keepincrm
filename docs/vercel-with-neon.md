# Розгортання на Vercel + Neon

Найпростіший спосіб запуску без власного сервера. Працює у безсерверному (serverless) режимі.

[![Deploy with Vercel](https://vercel.com/button)](https://vercel.com/new/clone?repository-url=https%3A%2F%2Fgithub.com%2Famssster%2Fibanlink-keepincrm&env=DATABASE_URL,APP_URL,SESSION_SECRET,WEBHOOK_ISSUE_SECRET,WEBHOOK_PAYMENT_SECRET,OWNER_PASSWORD)

## Кроки розгортання

1. Зареєструйтеся на [Neon.tech](https://neon.tech) та створіть проєкт PostgreSQL (регіон Франкфурт або найближчий до України).
2. Скопіюйте **Pooled connection string** (рядок з `-pooler` у хості).
3. Натисніть кнопку **Deploy with Vercel** вище.
4. Налаштуйте змінні за інструкцією нижче та виконайте Production-розгортання. Міграції бази виконуються автоматично під час Production-збірки.
5. Відкрийте постійну адресу сервісу з `/login` та налаштуйте реквізити.

## Environment Variables на Vercel

Вкажіть змінні під час створення проєкту або в **Project → Settings → Environment Variables**. Для кожної виберіть середовище **Production**, введіть назву в поле **Key**, значення — у **Value**, та збережіть. Для паролів, рядків підключення і секретів вибирайте тип **Secret**.

| Змінна | Як отримати та налаштувати |
|---|---|
| `DATABASE_URL` | **Обов’язкова.** Скопіюйте з Neon **Pooled connection string** для PostgreSQL та збережіть як Secret. Для входу потрібна доступна мігрована база. |
| `APP_URL` | Вкажіть постійну Production-адресу з **Project → Settings → Domains** разом із `https://`, без `/login` та інших шляхів. Купувати домен не потрібно: Vercel надає `*.vercel.app`. Адреси окремих deployment можуть змінюватися. Якщо змінну не задано, використовується `VERCEL_PROJECT_PRODUCTION_URL`, коли Vercel її надає. |
| `OWNER_PASSWORD` | Задайте надійний унікальний пароль для входу та збережіть як Secret. Альтернатива — `OWNER_PASSWORD_HASH`; якщо він заданий, `OWNER_PASSWORD` ігнорується. Без жодного з них увійти неможливо. |
| `SESSION_SECRET` | **Обов’язкова.** Згенеруйте окреме випадкове значення командою нижче та збережіть як Secret. Потрібні рівно 64 шістнадцяткові символи; зміна секрету робить наявні сесії недійсними. |
| `WEBHOOK_ISSUE_SECRET` | Згенеруйте окреме випадкове значення командою нижче та збережіть як Secret. Потрібне для webhook створення платіжних посилань. |
| `WEBHOOK_PAYMENT_SECRET` | Згенеруйте ще одне, інше випадкове значення та збережіть як Secret. Потрібне для webhook платежів. |
| `DB_POOL_MAX` | Необов’язкова. Для serverless можна встановити `2`; якщо не задано, код використовує `10`. |

Для `SESSION_SECRET` та кожного з двох webhook-секретів виконайте команду **окремо** і використайте три різні результати:

```sh
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

Ті самі webhook-секрети потрібно вказати в заголовках відповідних тригерів KeepinCRM; докладно — в [інструкції з налаштування вебхуків](keepincrm-webhooks.md). Не публікуйте секрети, пароль, рядок підключення чи скриншоти з ними. Якщо секрет або пароль розкрито, замініть його; webhook-секрет також оновіть у відповідному тригері KeepinCRM.

Замість відкритого пароля можна використати `OWNER_PASSWORD_HASH`: локально виконайте `npm run secrets`, скопіюйте лише значення `OWNER_PASSWORD_HASH` із `tmp/generated.env` у Vercel як **Secret**, а файл із секретами безпечно зберігайте або видаліть. Скрипт запитує пароль довжиною від 16 до 256 символів.

Після додавання або зміни змінних виконайте **Deployments → Redeploy**, потім відкрийте сервіс за постійною адресою з `APP_URL` і увійдіть із паролем власника.

Помилка **«Недозволене джерело запиту»** означає, що адреса сторінки не збігається з `APP_URL`. Перевірте протокол і домен, відкрийте саме адресу з `APP_URL` та після зміни змінних зробіть Redeploy. Якщо `APP_URL` не задано, застосунок використовує `VERCEL_PROJECT_PRODUCTION_URL`, коли Vercel надає цю змінну.

Для **Preview** задайте окремі `DATABASE_URL`, `SESSION_SECRET`, пароль власника і секрети вебхуків, не використовуйте production-базу та production-секрети. Міграції на Vercel Preview пропускаються: застосуйте `npm run migrate` до окремої preview-бази з довіреного середовища поза Vercel. `APP_URL` має точно збігатися з HTTPS origin preview-адреси; змінні Vercel не підставляють адресу поточного deployment автоматично. Якщо адреса змінюється, оновіть `APP_URL` та виконайте Redeploy; без збігу запити зі зміною даних відхиляються, а посилання і перенаправлення можуть вести на іншу адресу.

На хостингу Vercel потрібно окремо перевірити застосовні умови тарифу та забезпечити резервне копіювання бази Neon.

> **Примітка про Neon і Vercel Hobby:**
> - На безкоштовному тарифі Neon база засинає за відсутності активності та миттєво прокидається при першому запиті.
> - Усі запити та сповіщення обробляються синхронно прямо у вебхуку, що забезпечує однакову поведінку як на Vercel, так і в Docker.
> - Безкоштовний тариф Vercel Hobby призначений для некомерційного або тестового використання; для комерційного бізнесу рекомендується тариф Pro або власний VPS на Docker.
